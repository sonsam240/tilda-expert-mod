# Адаптивность и брейкпоинты

## Различие версий

**Документация:** [EN Zero](https://help.tilda.cc/zero) описывает пять диапазонов:

| Viewport | Grid из обзора |
|---|---:|
| ≥1200 | 1200 |
| 980–1199 | 980 |
| 640–979 | 640 |
| 480–639 | 480 |
| 320–479 | 320 |

Серые поля наследуют значения; изменённые для экрана выделяются. Адаптируются ширины текста/изображений, шрифты, координаты, высота артборда.

**MCP:** инструкция описывает `360,480,640,960,1200` для нового блока; без `ab_screens` — `320,480,640,960,1200`. Это контракт, не повод мигрировать существующий блок. Прочитай его `ab_screens`, проверь UI и media queries. Для 960,1200 фактический диапазон — 960–1199, а не 980–1199.

## Наследование MCP

- Самый широкий экран — базовые ключи без суффикса. Не пиши `width-res-1200`, если 1200 самый широкий.
- Остальные — `key-res-w`. Без override значение рекурсивно берётся с ближайшего более широкого экрана.
- Минимальный экран покрывает и более узкие окна; это не гарантирует отсутствие overflow ниже design width.
- `""` обычно отсутствие; исключения `ab_height_vh`, `ab_bgcolor`, `ab_bgimg` отключают настройку.
- Скрытие `y` наследуется; возврат видимости требует явного `n`, не пустой строки.
- `ab_flex` — верхний экран; не предполагай адаптивное переключение самого режима артборда. Direction/gap/размеры имеют адаптивные версии по контракту.

Пример: fontsize=48; fontsize-res-960=40; fontsize-res-480=28. На 700 →40, на 500 →28, на 400 →28 без отдельного override. Изменение 48 не изменяет 40/28. Удаление override возвращает наследование: проверь все более узкие экраны.

## Пользовательские точки

**Документация:** [анонс 30.01.2023](https://blog.tilda.cc/custom-breakpoints) подтверждает добавление/изменение/удаление экранов, максимум 10, 320–1920. Сетка для выбранного экрана: Zero Block Settings → Grid.

**MCP:** 2–10 точек 320–2560. Разница верхнего предела с историческим анонсом не устранена UI-тестом: 2560 подтверждено для контракта; редактор проверить отдельно.

UI-процедура: открыть настройки экранов текущего редактора, добавить/изменить/удалить точку, сохранить, проверить затронутые диапазоны. Не выдумывать подпись кнопки без открытого UI. MCP-процедура: backup; изменить `ab_screens` с обоснованием; сохранить/переименовать suffix keys; удалить только ненужные overrides; проверить границы. Новый максимальный экран меняет design width и смысл base keys.

## Проектирование — инженерная рекомендация

1. Desktop → узкие экраны, с отдельной композицией телефона при необходимости.
2. Текст → текст → кнопка в вертикальном flow; декор absolute с резервом.
3. Измерить строки после fonts; оценка `0.6*fontSize` на символ только черновая.
4. `Wcard=(Wavailable-(n-1)*gap)/n`; число колонок выбирай по читаемости контента.
5. Wrap нужен ограниченный W; Hug width родителя может исключать перенос.
6. Custom точку добавляй по дефекту/новой композиции, не по каждой модели телефона.

Приёмка: 320,360,390,479,480,639,640,768,959,960,979,980,1199,1200,1440,1920; custom ±1; высоты 568/667/900, landscape, zoom/text scaling, длинный язык, открытый popup. Оба набора границ проверяются намеренно: стандарт задания и реальные экраны.
